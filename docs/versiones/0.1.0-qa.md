# QA de la versión 0.1.0

Resultados de la QA de los Release Candidates de la `0.1.0` ([scope](0.1.0.md), checklist en [WORKFLOW.md](../../WORKFLOW.md) §5).

## Ronda 1 — `v0.1.0-rc.2` en Android (2026-10-20)

**Entorno:** emulador de Android Studio *Medium Phone API 37* (`sdk_gphone64_x86_64`, 1080×2400), build de desarrollo (`npx expo run:android`), backend local (perfil `dev`) contra PostgreSQL 17. Interacción automatizada con `adb` (toques, texto, capturas y árbol de accesibilidad).

### Fallos encontrados (corregidos en `v0.1.0-rc.3`)

| # | Gravedad | Fallo | Causa | Corrección |
|---|---|---|---|---|
| 1 | Bloqueante | Al abrir la app sin sesión aparecía "Unmatched Route" en lugar del login | La ruta inicial `/` estaba dentro del grupo protegido `(app)` | Ruta pública `/` que redirige a `/login` o `/home` |
| 2 | Bloqueante | Tras recargar la app con sesión iniciada también aparecía "Unmatched Route" | El layout raíz no montaba el navegador mientras se restauraba la sesión | El navegador se monta siempre; la carga se muestra en `/` |
| 3 | Bloqueante | Al crear un movimiento el formulario no se cerraba ("Respuesta inesperada del servidor"); al guardar otro, error de `Idempotency-Key` reutilizada y saldo del inicio sin actualizar | El backend devolvía `createdAt`/`updatedAt` a `null` en la creación (usaba la entidad sin gestionar tras `save()`); la app, que valida la respuesta, la rechazaba | El servicio responde con la entidad gestionada; tests de integración que comprueban esos campos |

Los tres tienen test de regresión o están cubiertos por la comprobación de arranque en frío.

### Resultado tras las correcciones

**App (Android)**

- [x] Arranque sin sesión → login; arranque en frío con sesión → inicio (3 veces seguidas)
- [x] Validación local: email no válido, campos obligatorios, importe con demasiados decimales (EUR "12,345", JPY "12,5")
- [x] Login con credenciales incorrectas → "Email o contraseña incorrectos."
- [x] Registro con contraseña común → rechazada; registro válido → inicio vacío
- [x] Alta de cuentas en EUR (2 decimales) y JPY (0 decimales) con su saldo inicial
- [x] Alta de ingreso y gasto; saldos correctos (100 € → 1.567,50 €; 20.000 JPY → 18.766 JPY)
- [x] Detalle de cuenta: movimientos más recientes primero, signo y color en los importes
- [x] Edición de un movimiento (formulario precargado) y borrado; saldos recalculados
- [x] No deja borrar una cuenta o categoría con movimientos; sí las vacías
- [x] Categorías: alta, nombre duplicado rechazado, borrado
- [x] Ajustes: cambio de divisa principal guardado en el servidor
- [x] Renovación automática de sesión al invalidarse el access token (reinicio del backend), sin pedir login
- [x] Cerrar sesión: no se restaura al reiniciar la app; volver a entrar conserva los datos
- [x] Borrar cuenta: contraseña incorrecta rechazada; con la correcta se borra todo y el login devuelve 401

**Accesibilidad**

- [x] Todos los botones, campos y opciones tienen etiqueta accesible (árbol de accesibilidad)
- [x] Errores de formulario anunciados como alerta
- [x] Texto al 150 %: sin cortes ni solapamientos en las pantallas revisadas
- [x] Áreas táctiles de 48 dp o más
- [ ] Recorrido completo con TalkBack activado (pendiente: hacerlo a mano)

**Integración y divisas**

- [x] Importes exactos en divisas de 0 y 2 decimales; formato con símbolo/código
- [ ] Divisa de 3 decimales (KWD) en la app (cubierta por tests de backend y de la app, no probada a mano)

### No cubierto en esta ronda

- iOS (simulador o dispositivo): requiere macOS.
- Dispositivo Android físico y versión mínima de Android.
- Comportamiento sin conexión (se probó el backend caído solo de forma indirecta).
- Rendimiento y batería en un dispositivo modesto.

### Observaciones (no bloqueantes)

- En JPY la app muestra el código ("20.000 JPY") en lugar del símbolo: es el formato estándar de `es-ES` en Intl.
- El emulador puede mostrar el tutorial de stylus de Gboard al escribir con `adb`; no es un fallo de la app.
